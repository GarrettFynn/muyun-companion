## ① 继续阅读队列（Reading tray）

**目标**：把续读记忆从"碰巧再打开那篇才生效"升级为"主动找回"——一个随时可开的在读列表。

**现有基础（代码锚点）**：
- `store[path] = { ts, ratio, readIdx, done }`（`saveCurrentPos` @ main.js），LRU 400 条已在库；
- 打开笔记回位逻辑 `restoreFor(file)` 已有——队列只需负责"打开"，回位自动发生。

**实现方案**：
- 新增命令 `继续阅读 · Continue reading`，打开一个 Modal（沿用既有 `MuyunHeatmapModal` 的 Modal 用法）；
- 数据：`Object.entries(this.store)` 按 `ts` 倒序取前 20；过滤 `done && ratio > 0.97` 的（读完的不出现在队列）；
- 行点击：`this.app.workspace.openLinkText(path, '')` → `restoreFor` 链路自动回位（file-open 事件已挂）；
- 行内"移出"按钮：`delete store[path]` + `saveStoreSoon()` + 行淡出（150ms）；
- 性能：打开时排序 400 条 <1ms，无任何常驻监听。

**界面设计**：
```
┌─ 继续阅读 ──────────────────────┐   宽 480px，Obsidian 原生 Modal；
│ ▸ 2026-10-14 · MuYun 设计文档      │   每行三段：
│   ▓▓▓▓▓▓▓▓░░░░  62%         ✕  │   文件名（超长省略，title 显全路径）
│ ▸ 2026-10-13 · 读书笔记/百年孤独   │   + 微缩进度条（6px 高，ratio 上色）
│   ▓▓▓▓░░░░░░░░  31%         ✕  │   + 相对时间（"3 小时前"，muted 小字）
│ …（最多 20 行）                    │   ✕ = 移出（hover 才显）
└────────────────────────────────┘   空态：居中一句"最近没有在读的笔记"。
```
- 进度条色 `var(--interactive-accent)`；时间文字 `var(--text-faint)`；hover 行背景 `var(--background-modifier-hover)`——全部标准变量，任意主题可用。

**决策点 D1**：入口放哪？建议 a) 命令面板 + b) 点击状态栏 `📖` 计数直接开队列（statsEl 绑 click，零新增 UI）。可选 c) 左侧栏 ribbon 图标（更显眼但占位）。

**边界与降级**：笔记被重命名/移动 → `store` 键失效 → 行点击提示"笔记不存在"并自动移出；不做反向清理（LRU 自然淘汰）。

## ② 已读标记（文件树徽标）

**目标**：读完的笔记在文件树一眼可辨，配合 MuYun 文件树骨架视觉。

**现有基础**：`store[path].done` 已有（读完柔光彩蛋的触发点即置位，`updateProgress` @ main.js）。

**实现方案**：
- 监听 `layout-change`（既有 debounce 300ms 节流）+ `file-open` 后追加一步 `markReadFiles()`；
- `markReadFiles()`：`querySelectorAll('.nav-file-title')` 一次遍历，`dataset.path` 在 store 且 `done` → `addClass('muyun-read')`，否则移除；
- 性能：500 文件库实测预算 ~2ms/次（单次类名切换，无布局读写交替）；千级文件 <5ms；
- CSS（styles.css）：三选一（见决策点 D2）。

**界面设计（三个候选）**：
- **A. 文件名后缀 ✓**：`.muyun-read .nav-file-title-content::after { content: ' ✓'; color: var(--text-faint); }`——信息最明确，微侵入；
- **B. 文件名转 muted**：已读文件文字降为 `var(--text-muted)`——最克制，但"读完=不重要"的暗示可能不符阅读型库的价值观；
- **C. 左缘小点**：文件名前 3px 圆点（accent 色）——与 MuYun 主题的"当前文件左条"视觉语言同族，但与活动标记有混淆风险。

**决策点 D2**：A / B / C 选一。建议 **A**（明确、无歧义、视觉最轻）。

**边界与降级**：重命名后 `store` 键失效 → 徽标自然消失（等价于"未读"重置，可接受）；文件树折叠/滚动由 Obsidian 自管，我们只在刷新点重跑。

## ③ 连续阅读天数（streak 常驻）

**目标**：让"连续在读"可见，形成轻量习惯激励。

**现有基础**：`calcStreak(now)` **已存在**（v0.4 实现，周报在用，main.js @「连续达成天数」）——本项是纯露出，无新计算。

**实现方案**：
- `updateStatsStatus()` 扩展：`📖 25/30m · 🔥7`（streak ≥2 时才显示，1 天不挂火）；
- 热图弹窗顶部加一行大号展示：`🔥 7 天连续阅读 · 7-day streak`；
- 设置开关 `streakInStatus`（默认开；仅 `statsEnabled` 开启时有效——统计关则无数据，顺带隐藏）；
- 性能：零新增计算（复用每次 updateStatsStatus 已有路径）。

**界面设计**：🔥 emoji 与 📖 风格一致（状态栏 emoji 约定）；热图弹窗中 streak 行用 14px 加粗，下方 12px muted 英文对照。

**决策点 D3**：断签要不要提醒（"昨天没读，streak 归零"Notice）？**建议不做**——负面提醒对阅读型产品是反激励，且打断感强。若要做，默认关 + 设置项。

## ④ 统报导出（markdown 报告）

**目标**：把本地统计变成可留存、可回顾的笔记。

**实现方案**：
- 新增命令 `导出阅读周报 Export weekly report`（v1 只做周报；年报复用同模板换时间窗，v1.1 再加）；
- 生成 `阅读统计/阅读周报 2026-W42.md`（文件夹不存在则创建，`app.vault.createFolder`；文件名带 ISO 周号，不覆盖历史）；
- 内容模板：时间窗汇总（总时长/日均/达成天数）、streak、Top 10 笔记表（`| 笔记 | 时长 |`）、12 周热图的文本近似（每行 7 格 emoji：`🟪🟪⬜…` + 周起始日期）；
- 写入后 `workspace.openLinkText` 直接打开产文（即写即看，不需要 Notice 找文件）；
- 性能：一次性生成 <1ms 纯字符串拼接 + 单文件写入。

**界面设计**：无新 UI——**产出物即界面**。模板头部固定：

```markdown
# 阅读周报 · 2026-10-06 ~ 10-12
> MuYun Companion 本地生成 · 数据仅来自本库
本周合计 **3h 42m** ｜ 日均 **32m** ｜ 目标达成 **6/7 天** ｜ 🔥 streak **12**
```

**决策点 D4**：导出文件夹默认 `阅读统计/` 是否符合你的库结构习惯？（可在设置改，`reportFolder` 文本项，默认值需拍板。）

**边界与降级**：统计关闭时命令置灰提示"先开启阅读统计"；同名文件已存在（同一周重复导出）→ 追加时间后缀 `-2` 不覆盖。

## 版本规划建议

- **方案甲**：四项一次打包发 0.7.0（工作量 ≈ 0.6.0 的七成，风险集中在 ② 的文件树遍历）；
- **方案乙**：①③（几乎零风险，纯露出/纯 Modal）先发 0.7.0，②④ 跟 0.8.0。
- 建议**甲**——四项互相独立，回滚面小，且都是小体量。
